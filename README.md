# ReferyTale

> 書き手の事実・語彙・視点を壊さず、自然な日本語へ仕上げるためのCodex Skillです。

ReferyTaleは、note・ブログ・エッセイ・コラム・メール・報告書などの日本語文章を、書き手が実際に持っている材料の範囲で整えるためのSkillです。

AIが文章を「うまく」しようとする過程では、本人が話していない経験を補ったり、もっともらしい原因を足したり、キャッチーな造語を作ったり、人物固有の文体を平均的な文章へならしたりすることがあります。

ReferyTaleは、文章の自然さを次の4軸で扱います。

- **Source Fidelity** — 書き手が話していない事実・経験を増やさない
- **Vocabulary Provenance** — AIが勝手に造語・概念名を作らない
- **Voice Fidelity** — 人物・ブランド・媒体固有の声を平均化しない
- **Writing Quality** — 読みにくさと、AI特有の「整いすぎ」を減らす

- 表示名: `ReferyTale`
- skill名: `referytale`
- GitHubリポジトリ名: `codex-skill-referytale`

## まず試す

Codexに次のように依頼して、GitHubリポジトリからインストールします。

```text
$skill-installer install https://github.com/alka0000-dev/codex-skill-referytale
```

インストール後にSkillが表示されない場合は、Codexを再起動してください。

文章作成・推敲の依頼の先頭に `$referytale` を付けます。

```text
$referytale このメモを、書いていない経験を足さずにnote記事へ整えてください。
```

既存文章のリライトにも使えます。

```text
$referytale この文章を、意味と自分の言い回しを残しながら自然にしてください。
```

## ReferyTaleが防ぐ問題

文章としては読みやすくても、書き手本人の文章ではなくなることがあります。

- 入力にない出来事・発言・感情を補う
- 「かもしれない」を確定的な原因へ変える
- 「○○力」「○○パラドックス」などの新しい概念名をAIが勝手に作る
- ユーザー自身が使った独自表現を、一般語ではないという理由で消す
- 人物Skillの文体より、汎用的な「読みやすい文章」を優先する
- 個人的な体験を、普遍的な教訓やチェックリストへ変える
- 全段落を同じ厚み・同じ文型へ整える

ReferyTaleは、単にAIらしい表現を消すのではなく、**文章の材料と声の出所を保ったまま自然にする**ことを重視します。

## 他の人物・ブランドSkillとの関係

ReferyTaleは文章品質の基盤です。

人物、ブランド、媒体、プロジェクトに特化したSkillが同時に適用される場合、そのSkillが持つ次の情報を優先します。

- 事実
- 経験
- 視点
- 語彙
- 口調
- 媒体固有の表現

```text
人物・ブランド・媒体Skill
    └─ 誰として、何を、どんな声で書くか

ReferyTale
    └─ その材料と声を壊さず、どう自然に仕上げるか
```

たとえば人物Skillが「個人的な場面から入り、結論を急がない」と定義している場合、ReferyTaleが一般的な文章ルールを理由に結論先行へ変更しません。

ただし、固有Skillに存在しない個人的な事実・経験・感情を人物像から推測して追加することもしません。

固有Skillの一人称、口調、語彙、リズム、構成、比喩の頻度、導入や結び方は表現規則として引き継ぎます。一方、非フィクションで人物が実際に何をしたか、何を言ったか、何を感じたか、どのような性格・状態だったかは具体情報として扱い、「その人物らしい」という理由だけでは追加しません。材料は「何を言えるか」、固有Skillは「それをどう言うか」を決めます。明示されたフィクションでは、設定とキャラクター性に反しない範囲で新しい言動を作れます。

## 無断造語を防ぐ

ReferyTaleは、新しい言葉を絶対に使わないSkillではありません。

本文で目立つ概念語は、次の順で扱います。

```text
ユーザーが使った語
  ↓
適用中の人物・プロジェクトSkillの語
  ↓
一次資料・引用元の語
  ↓
一般に確立している語
  ↓
普通の説明文
```

1〜4のどれにも該当する語がない場合は、普通の説明文を使います。

ユーザーが命名を求めていない限り、AIがその代わりとして新しい概念名を作ることはしません。

たとえばユーザー自身が「他責力」という表現を使っている場合、それはユーザー語として保持できます。

一方、AIが文章をキャッチーにするためだけに「期待疲労」「AI空白消失症候群」のような言葉を作ることは避けます。

命名自体を依頼された場合は、新しい名称を**提案名**として作ることができます。

その場合も、各提案名へ普通の説明文を添え、名称なしで一案ずつ読み返します。すべての案がそれぞれ単独で、元の対象の主体・動作・原因・時間関係・結果を欠かさず保っていることを確認します。新しいのは名前だけで、指している内容は依頼の範囲に保ちます。

## 対応表はどう扱うか

ReferyTaleでは、note・ブログなど日常の文章制作を重くしないため、対応表を毎回必須にはしません。

普段の文章では、事実・経験・語彙の出所を執筆前後に確認します。

一方、次の場合は **Provenance Table モード**を使います。

- 「厳密に」「根拠を追えるように」「出所を確認して」と指定された
- 対外文書や重要な非フィクション
- 長文
- 複数資料・複数Skillをまたぐ
- 独自表現や未確認事項が多い

対応表は一表です。

```text
ID / 内容 / 種類 / 出所区分 / 出所の識別子・箇所 / 確度 / 本文での扱い
```

これは名前を決めるための表ではなく、**本文の材料がどこから来たかを追跡する表**です。

明示的な命名タスクでは、名前を先に作って意味を後付けせず、先に何を指すのかを具体的に確認してから提案名を作ります。

## Codexが行うこと

ReferyTaleは、文章を次の順番で扱います。

1. 今回使ってよい事実・経験・意見・語彙を確認する
2. 同時適用中の人物・ブランド・媒体Skillのルールを確認する
3. 材料の範囲内で初稿を書くが、まだユーザーへ返さない
4. 初稿とは別の工程で、タイトル・見出し・本文の意味内容を材料へ照合し、遡れない内容を削除する
5. 使用できる内容だけを人物Skillの表現規則でつなぎ直し、新しい内容を足さずに自然さを整える
6. 修正後も素材外の内容が残る場合は、材料だけの短い文章へ戻してから最終確認する

重要な文章では、本文を書く前にProvenance Tableへ主要材料を整理します。

重要な非フィクションや同じ失敗が繰り返された文章では、利用可能な範囲で初稿作成と出所照合を別の検証担当へ分けます。検証担当には材料、人物Skillの表現規則、初稿だけを渡し、初稿を作った理由で内容を正当化しません。

## 使う場面

- note・ブログ・エッセイ・コラムを書く
- メモから文章を書き起こす
- 既存文章をリライト・推敲する
- 「AIっぽい」「不自然」「もっと自分らしく」と言われた文章を直す
- 人物・ブランドSkillと組み合わせて文章を書く
- 造語を増やさず、既存の語彙で説明したい
- 元の事実・経験・意見を変えずに読みやすくしたい
- 新しい名称を付ける前に、何を指すのかを整理したい

## 使わない場面

- 翻訳だけを行う
- Markdownや改行だけを機械的に変更する
- コード生成だけを行う

創作タスクにも、自然さ、既存設定、キャラクターの言動や声を保つために使えます。その場合はReferyTaleの「非フィクションの事実を増やさない」制約をそのまま適用せず、明示された創作範囲と既存設定を区別して扱います。

## 評価

evalでは、次の失敗を個別に確認します。

- 入力にない経験を追加した
- 不明な原因や感情を断定した
- AI独自の造語を導入した
- ユーザー由来の独自表現を消した
- 固有Skillより汎用文体を優先した
- 個人の体験を一般論・教訓へ変えた
- 同じ文型・段落構造を反復した
- 元の主張の強さや不確実性を変えた

`evals/evals.json` に33ケースを収録しています。GPT-5.6-sol・lowによる最新の全件比較では、Skillなし16/33に対してSkillあり33/33でした。改善17件、同等16件、悪化0件で、生成エラーと作業領域への副作用も0件です。

実行条件、評価定義、採点、実出力、内容ハッシュを含む公開レポートは、[`evals/results/2026-09-05-gpt-5.6-sol-full-v0.2.3/report.md`](./evals/results/2026-09-05-gpt-5.6-sol-full-v0.2.3/report.md)に置いています。現行版へ至るまでに不合格が残った出力も、[`evals/results/history/README.md`](./evals/results/history/README.md)から追えるようにしています。これは同一モデルによる自動採点であり、人手評価や他モデルを含む一般性能を示すものではありません。再実行方法と全成果物は[`evals/README.md`](./evals/README.md)を参照してください。

## natural-japaneseとの関係

現在版ReferyTaleの検討にあたり、[coji/natural-japanese](https://github.com/coji/natural-japanese) の考え方を参考にしています。

特に、生成後の言い換えだけでなく執筆前後に品質確認を置くこと、AI特有の反復・過剰な均一化を文章品質として扱うこと、evalでルールを検証する姿勢を参考にしました。

ReferyTaleでは、同Skillの工程名、12箇条、検出スクリプトなどを複製せず、Source Fidelity / Vocabulary Provenance / Voice Fidelity / Writing Quality の4軸として独自に再設計しています。

詳細は [ACKNOWLEDGEMENTS.md](./ACKNOWLEDGEMENTS.md) を参照してください。
