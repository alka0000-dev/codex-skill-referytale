# ReferyTale

> 書き手の事実・語彙・視点を壊さず、自然な日本語へ仕上げるためのCodex Skillです。

ReferyTaleは、note、ブログ、エッセイ、コラム、メール、報告書などの日本語文章を、書き手が実際に持っている材料の範囲で整えるときに使います。

AIが文章を読みやすくしようとすると、本人が話していない経験や原因を補い、目を引く造語を作り、人物固有の言い回しを平均的な文体へならすことがあります。ReferyTaleは、文章の材料と声の出所を保ったまま、不自然さだけを減らします。

## まず試す

Codexに次のように依頼して、GitHubリポジトリからインストールします。

```text
$skill-installer install https://github.com/alka0000-dev/codex-skill-referytale
```

インストール後にSkillが表示されない場合は、Codexを再起動してください。

文章作成や推敲の依頼の先頭に`$referytale`を付けます。

```text
$referytale このメモを、書いていない経験を足さずにnote記事へ整えてください。
```

既存文章のリライトにも使えます。

```text
$referytale この文章を、意味と自分の言い回しを残しながら自然にしてください。
```

## 使うかどうかの目安

次のような文章作業に向いています。

- 入力にない出来事、発言、感情、原因を補ってほしくない
- 「かもしれない」を断定へ変えてほしくない
- AIが「○○力」「○○症候群」などの概念名を勝手に作るのを防ぎたい
- 自分が使った独自表現は、そのまま残したい
- 人物、ブランド、媒体のSkillが定める声を優先したい
- 個人的な体験を一般論や教訓へ変えてほしくない
- AIらしい反復、過剰整理、均一な段落を減らしたい
- 新しい名前を提案する前に、何を指すのか整理したい

翻訳だけ、Markdownや改行だけの機械的な変更、コード生成だけを行う作業には使いません。

創作では、既存設定とキャラクターの声を保つために使えます。その場合、非フィクションの「事実を増やさない」という制約をそのまま当てはめず、依頼された創作範囲と既存設定を分けて扱います。

## ReferyTaleがすること

ReferyTaleは、自然さを4つの軸で扱います。

| 確認すること | 文章への反映 |
| --- | --- |
| Source Fidelity | 書き手が示していない事実、経験、感情、原因を増やさない |
| Vocabulary Provenance | ユーザー、固有Skill、資料、確立語にない概念名を無断で作らない |
| Voice Fidelity | 人物、ブランド、媒体固有の語彙、口調、構成を平均化しない |
| Writing Quality | 意味と声を保ったまま、反復、過剰整理、過剰説明を減らす |

人物、ブランド、媒体、プロジェクトに特化したSkillが同時に使われる場合、固有Skillが「誰として、何を、どんな声で書くか」を決め、ReferyTaleが「その材料と声を壊さず、どう自然に仕上げるか」を支えます。

固有Skillの一人称、口調、語彙、リズム、構成、比喩の頻度、導入や結び方は表現規則として引き継ぎます。一方、人物が何をしたか、何を言ったか、何を感じたかは具体情報として扱い、「その人物らしい」という理由だけでは追加しません。

## natural-japaneseとの関係

ReferyTaleは、[coji/natural-japanese](https://github.com/coji/natural-japanese)の考え方を参考にし、自分の用途に合わせて再設計・拡張したSkillです。

出発点にしたのは、主に次の考え方です。

- 生成後の言い換えだけでなく、執筆前後に品質確認を置く
- AI特有の反復、過剰な均一化、翻訳調を文章品質として扱う
- 機械的な検出と文脈上の判断を分ける
- コーパスやevalでルールを検証する

ReferyTaleでは、これらをSource Fidelity、Vocabulary Provenance、Voice Fidelity、Writing Qualityの4軸へ広げました。natural-japaneseの工程名、12箇条、検出スクリプト、文章そのものを再配布したものではありません。

## 使い方

材料、書き手や媒体、完成形が分かると、文章を変えてよい範囲を判断しやすくなります。すべてを細かく決める必要はありません。分かる範囲だけでも、次のように伝えられます。

```text
$referytale
材料: （文章に使ってよいメモ、事実、資料）
声: （本人の文体サンプル、人物・ブランド・媒体Skill）
完成形: （note記事、メール、リライト、診断など）
```

通常の文章では、事実、経験、語彙の出所を執筆前後に確認します。「厳密に」「根拠を追えるように」と指定された場合や、対外文書、重要な非フィクション、長文、複数資料を扱う場合はProvenance Tableを使います。

表は、内容、種類、出所、確度、本文での扱いを一か所にまとめるためのものです。新しい名前を作って意味を後付けするためには使いません。

命名自体を依頼された場合は、新しい名称を提案できます。その場合も、各候補が指す主体、動作、原因、時間関係、結果を元の材料から変えず、名前のない普通の説明を添えます。

## 完了時に確認できること

文章作成やリライトを依頼した場合、ReferyTaleは最終稿を返す前に次を確認します。

- タイトル、見出し、本文の意味内容が、使用できる材料へ遡れる
- 材料にある主体、対象、順序、因果、不確実性、評価の強さが保たれている
- AI独自の名称を無断で作らず、ユーザーや固有Skill由来の語を不用意に消していない
- 固有Skillの声と具体的な構成指定を、材料を増やさず反映している
- 同じ内容を要約、強調、評価、オチとして繰り返していない
- 自然さを整えた後も、出所、意味、声が崩れていない

「この文章はAIっぽいか」「造語していないか」など、診断だけを依頼した場合は本文を書き換えません。4軸ごとに、問題なし、軽い懸念、要修正、判定不能のいずれかと、根拠または不足している材料を示します。

## 比較評価の結果

2026年9月5日に、GPT-5.6-sol・lowで38ケースを各条件1回ずつ実行しました。公開後の内容確認による訂正後は、ReferyTaleなしが15/38、ありが37/38です。改善23件、同等14件、悪化1件で、生成エラーと作業領域への副作用はありませんでした。

| 確認項目 | ReferyTaleなし | ReferyTaleあり |
| --- | ---: | ---: |
| 指定された評価基準を満たした出力 | 15/38 | 37/38 |
| 生成に成功した出力 | 38/38 | 38/38 |
| 作業領域への副作用 | 0件 | 0件 |

評価では、素材外の補完、無断造語、人物Skillの継承、意味や主張の強さの保持、自然さ、診断時の材料不足、非対象作業への不干渉を確認しています。

### この結果からは分からないこと

この数値は、記載したモデル、ケース、実行回数の範囲に限られます。同じモデルによる自動採点と同じタスク内の内容監査であり、独立した人手評価や別モデルを含む一般性能を示すものではありません。

公開後の確認では、人物Skillの導入指定を満たさなかったp18と、対照出力が元の動作を保持しなかったp26を不合格へ訂正しました。その後、p18の修正版だけをReferyTaleありで3回評価し、3/3で合格しましたが、全38ケースは再実行していません。

現在の`SKILL.md`は、通常利用時の読み込み量を減らすため、この全件評価後に軽量化しています。中核規則と評価項目の静的照合は行いましたが、軽量化後の全文をモデルで再評価していないため、37/38は現在ファイルの直接的な性能値ではありません。
