# 保守モード開始機能 設計

## 1. 目的

変更承認記録、アクティブな利用者セッションの件数、および予定開始時刻を確認し、元の要求で指定された三つの条件をすべて満たす場合だけ、管理サービスへ保守モード開始要求を送る。送信後は、管理サービスから保守モードを開始済みであることを示す応答を受けるまで、同じ要求を再送しない。要求の送信と応答の結果は監査できるように保存する。

## 2. 先行草稿の扱い

先行草稿の「保守移行点」は採用しない。この語だけでは、次のどれを指すか一意に決まらないためである。

- 三つの開始条件をすべて満たしたこと
- 管理サービスへ要求を送った事象
- 要求送信後から開始済みの応答を受ける前までの状態

設計では、これらを別の名称と役割に分ける。

## 3. 名称と定義

| 名称 | 役割 | 定義 |
|---|---|---|
| 変更承認済み条件 | 開始条件 | 変更承認記録が承認済みであること。 |
| 利用者セッション不在条件 | 開始条件 | アクティブな利用者セッションの件数が0件であること。 |
| 予定開始時刻到達条件 | 開始条件 | 現在時刻が予定開始時刻に達していること。 |
| 保守開始要求送信条件 | 開始条件 | 変更承認済み条件、利用者セッション不在条件、および予定開始時刻到達条件をすべて満たしていること。 |
| 保守モード開始要求送信 | 事象 | 保守開始要求送信条件を満たした後、管理サービスへ保守モード開始要求を1回送ること。 |
| 開始済み応答待ち状態 | 状態 | 保守モード開始要求送信の後、管理サービスから保守モードを開始済みであることを示す応答を受ける前までの状態。 |
| 開始済み応答受信 | 事象 | 管理サービスから保守モードを開始済みであることを示す応答を受けること。 |
| 要求ID | 値 | 管理サービスへ送った保守モード開始要求を識別する値。 |
| 送信時刻 | 値 | 管理サービスへ保守モード開始要求を送った時刻。 |
| 管理サービスの応答結果 | 値 | 管理サービスから受けた応答の結果。 |
| 保守モード開始監査記録 | 記録 | 要求ID、送信時刻、および管理サービスの応答結果を監査用に保存した記録。 |

「開始済み応答待ち状態の間は、送信済みのものと同じ要求を送らない」という規則には、状態や事象と混同する独立名称を付けず、そのまま記述する。

## 4. 開始判定

保守開始要求送信条件は、次の論理積で判定する。

```text
変更承認済み条件
AND 利用者セッション不在条件
AND 予定開始時刻到達条件
```

いずれか一つでも満たさない場合、管理サービスへ保守モード開始要求を送らない。

## 5. 処理順序

1. 変更承認済み条件、利用者セッション不在条件、および予定開始時刻到達条件を確認する。
2. 三つすべてを満たさない場合は、要求を送らずに判定を終える。
3. 三つすべてを満たし、同じ要求について開始済み応答待ち状態でない場合に限り、保守モード開始要求送信を行う。
4. 保守モード開始要求送信の際に、要求IDと送信時刻を保守モード開始監査記録へ保存する。
5. 送信後は開始済み応答待ち状態とする。この状態の間に同じ要求について再度開始判定が行われても、同じ要求を送らない。
6. 管理サービスから応答を受けたら、管理サービスの応答結果を保守モード開始監査記録へ保存する。
7. 受けた応答が保守モードを開始済みであることを示す場合、開始済み応答受信として開始済み応答待ち状態を終える。開始済みであることを示さない応答では、この状態を終えず、同じ要求を送らない。

## 6. 監査用に保存する内容

| 値 | 保存する時点 |
|---|---|
| 要求ID | 保守モード開始要求送信の時点 |
| 送信時刻 | 保守モード開始要求送信の時点 |
| 管理サービスの応答結果 | 管理サービスから応答を受けた後 |

要求IDを使って、送信時に保存した値と、その要求に対する管理サービスの応答結果を同じ保守モード開始監査記録として追跡できるようにする。

## 7. 受け入れ基準

- 三つの開始条件をすべて満たす場合に限り、管理サービスへの保守モード開始要求が1回送られる。
- 三つの開始条件のうち一つでも満たさない場合、要求は送られない。
- 保守モード開始要求送信の後、開始済み応答受信より前に同じ開始判定が再度行われても、同じ要求は送られない。
- 管理サービスから開始済みであることを示さない応答を受けても、同じ要求は送られない。
- 要求ID、送信時刻、および管理サービスの応答結果を監査用に確認できる。

## 8. 元の要求では未決定の事項

次の事項は元の要求に定めがないため、この設計では確定しない。

- 管理サービスへ要求を送れなかった場合の再試行方法
- 開始済みであることを示さない応答を受けた後の終了方法
- 応答が複数回届いた場合に、すべて保存するか最新の結果だけを保存するか
- 保守モード開始監査記録の保存先と保存期間
- 要求送信、開始済み応答待ち状態への変更、および監査用保存の間で必要となる一貫性の実現方法
- プロセス再起動時や複数の実行主体が同時に判定する場合に、同じ要求を識別して再送を防ぐ範囲
