# 保守モード開始機能 設計

## 目的

変更承認、利用者セッション数、予定開始時刻を確認し、三つの開始条件をすべて満たした場合だけ管理サービスへ保守モード開始要求を送る。送信後は、管理サービスから開始済みの応答を受けるまで同じ要求を再送せず、要求と応答の結果を監査できるようにする。

## 名称と定義

| 名称 | 役割 | 定義 |
|---|---|---|
| 変更承認済み条件 | 開始条件 | 変更承認記録が承認済みであること。 |
| 利用者セッションゼロ条件 | 開始条件 | アクティブな利用者セッションの件数が0件であること。 |
| 予定開始時刻到達条件 | 開始条件 | 現在時刻が予定開始時刻に達していること。 |
| 保守モード開始要求送信 | 事象 | 三つの開始条件をすべて満たした場合だけ、管理サービスへ保守モード開始要求を1回送ること。 |
| 開始済み応答待ち状態 | 状態 | 保守モード開始要求送信の後、開始済み応答受信の前であり、同じ要求を再送しない状態。 |
| 開始済み応答受信 | 事象 | 管理サービスから保守モードを開始済みである旨の応答を受けること。 |
| 要求ID | 値 | 管理サービスへ送る保守モード開始要求を監査で識別する値。 |
| 送信時刻 | 値 | 管理サービスへ保守モード開始要求を送った時刻の値。 |
| 管理サービス応答結果 | 値 | 管理サービスから受けた応答の結果を表す値。 |
| 保守モード開始監査記録 | 記録 | 要求ID、送信時刻、管理サービス応答結果を保存した監査用の記録。 |

## 開始条件の判定

次の三つを個別に評価する。

1. 変更承認済み条件
2. 利用者セッションゼロ条件
3. 予定開始時刻到達条件

一つでも満たさない場合、保守モード開始要求送信は行わない。三つをすべて満たした場合だけ、保守モード開始要求送信を行う。ただし、同じ要求について開始済み応答待ち状態である場合は、三つをすべて満たしていても再送しない。

次表は、同じ要求について開始済み応答受信となる前の判定に適用する。

| 三つの開始条件 | 同じ要求について開始済み応答待ち状態か | 動作 |
|---|---|---|
| 一つ以上を満たさない | いずれでもよい | 送信しない |
| すべて満たす | はい | 同じ要求を再送しない |
| すべて満たす | いいえ | 保守モード開始要求送信を行う |

## 送信後の動作

1. 保守モード開始要求送信に使用した要求IDと送信時刻を、保守モード開始監査記録へ保存する。
2. 保守モード開始要求送信の後、開始済み応答待ち状態となる。
3. 開始済み応答待ち状態では、同じ要求の保守モード開始要求送信を行わない。
4. 管理サービスから応答を受けたら、その管理サービス応答結果を保守モード開始監査記録へ保存する。
5. 受けた応答が開始済みの応答である場合は開始済み応答受信となり、開始済み応答待ち状態を終える。
6. 受けた応答が開始済みを示さない場合、開始済み応答受信にはならず、同じ要求を再送しない。

## 監査用に保存する内容

| 保存項目 | 保存する時点 | 内容 |
|---|---|---|
| 要求ID | 保守モード開始要求送信に伴う時点 | 送った要求を識別する値 |
| 送信時刻 | 保守モード開始要求送信に伴う時点 | 要求を送った時刻の値 |
| 管理サービス応答結果 | 管理サービスから応答を受けた後 | 受けた応答の結果を表す値 |

三項目は保守モード開始監査記録として保存する。保存媒体、保持期間、および応答を複数回受けた場合の保存方法は元要求に定めがないため、本設計では確定しない。

## 元要求で確定していない事項

次の事項は名称で補完せず、未確定のままとする。

- 開始条件を評価する契機と頻度
- 現在時刻と予定開始時刻の時計およびタイムゾーン
- 要求IDの生成方法と値の形式
- 管理サービスとの通信方式
- タイムアウト時および開始済みを示さない応答を受けた後の扱い
- 開始済み応答待ち状態を保持する媒体と期間
- 保守モード開始監査記録の保存媒体、保持期間、および複数応答の保存方法

これらを決定するときも、「開始済み応答受信までは同じ要求を再送しない」という順序を変更してはならない。

## 先行草稿の扱い

先行草稿の「保守移行点」は、三つの開始条件と送信後の状態のどちらを指すか一意に定まらないため、名称として採用しない。「開始処理」は管理サービスへの要求送信を明示しないため、保守モード開始要求送信へ置き換える。「結果を記録する」は保存対象が不足しているため、要求ID、送信時刻、管理サービス応答結果を保存する記述へ置き換える。
