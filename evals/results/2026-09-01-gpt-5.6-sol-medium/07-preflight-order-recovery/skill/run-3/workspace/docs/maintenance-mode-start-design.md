# 保守モード開始機能 設計

## 1. 目的

変更承認、利用者セッション、予定開始時刻を確認し、三つの開始条件がすべて成立した場合だけ管理サービスへ保守モード開始要求を送る。送信後は、管理サービスから保守モード開始済み応答を受けるまで同じ要求を再送せず、送信と応答の結果を監査できるようにする。

## 2. 用語

| 名称 | 定義 |
|---|---|
| 変更承認済み条件 | 変更承認記録の状態が承認済みであるという開始条件。 |
| 利用者セッション不在条件 | アクティブな利用者セッションの件数が0であるという開始条件。 |
| 予定開始時刻到達条件 | 現在時刻が予定開始時刻と同じか、それより後であるという開始条件。 |
| 保守モード開始許可条件 | 上記三つの開始条件がすべて成立しているという開始条件。 |
| 保守モード開始要求送信 | 管理サービスへ保守モード開始要求を送る事象。 |
| 開始済み応答待ち状態 | 保守モード開始要求送信後、管理サービスから開始済みを示す応答をまだ受けていない状態。 |
| 保守モード開始済み応答受信 | 管理サービスから保守モードが開始済みであることを示す応答を受ける事象。 |
| 保守モード開始監査記録 | 要求ID、送信時刻、管理サービス応答結果を関連付けて保存する一つの監査用記録。 |
| 要求ID単位の条件付き記録作成 | 同じ要求IDを持つ記録が存在しない場合に限り一つの記録を新規作成し、作成に成功した実行主体だけが要求を送る手段。 |

「保守移行点」は使用しない。この語は、送信前の開始条件と送信後の待機状態のどちらを指すか一意に決まらないためである。

## 3. 開始条件

保守モード開始許可条件は、次の論理積とする。

```text
変更承認済み条件
AND 利用者セッション不在条件
AND 予定開始時刻到達条件
```

| 変更承認済み条件 | 利用者セッション不在条件 | 予定開始時刻到達条件 | 保守モード開始要求送信 |
|---|---|---|---|
| 成立 | 成立 | 成立 | 4節の手順3へ進む |
| それ以外 | 任意 | 任意 | 行わない |
| 任意 | それ以外 | 任意 | 行わない |
| 任意 | 任意 | それ以外 | 行わない |

条件を評価できない場合は成立として扱わず、保守モード開始要求送信を行わない。

## 4. 処理順序

1. 変更承認記録の状態、アクティブな利用者セッションの件数、予定開始時刻、現在時刻を取得する。
2. 三つの開始条件を個別に評価する。一つでも成立しない、または評価できない場合は要求を送らず終了する。
3. 三つすべてが成立した場合、要求ID単位の条件付き記録作成を行う。同じ要求IDの保守モード開始監査記録が存在しない場合に限って一つの記録を作成する。
4. 同じ要求IDの記録がすでに存在する場合は、要求を送らず終了する。保存処理自体が失敗した場合も要求を送らず、運用上の異常として通知する。
5. 記録作成に成功した実行主体は、送信時刻を同じ記録へ保存してから、その要求IDを使って保守モード開始要求送信を行う。
6. 送信後は開始済み応答待ち状態とする。この状態は永続化した記録から判定し、プロセス再起動後も同じ要求を送らない。
7. 管理サービスから応答を受けたら、管理サービス応答結果を同じ記録へ保存する。
8. 保守モード開始済み応答受信が発生した場合、開始済み応答待ち状態を終了する。開始済みを示さない応答の場合、応答結果は保存するが、元要求どおり同じ要求を自動再送しない。

要求ID単位の条件付き記録作成は、複数の実行主体が同時に成功しない原子的な操作でなければならない。

## 5. 状態と送信可否

| 保守モード開始監査記録 | 送信時刻 | 管理サービスから開始済みを示す応答 | 状態 | 同じ要求の送信可否 |
|---|---|---|---|---|
| なし | なし | なし | 要求送信前 | 保守モード開始許可条件が成立した場合だけ送信可 |
| あり | 未設定 | 未受信 | 要求送信前に停止 | 自動送信不可。7節に示す未決定の復旧方法で扱う |
| あり | 設定済み | 未受信 | 開始済み応答待ち状態 | 送信不可 |
| あり | 設定済み | 受信済み | 保守モード開始済み応答受信後 | 送信処理は完了済み |

## 6. 監査記録

| 項目 | 必須となる時点 | 内容 |
|---|---|---|
| 要求ID | 記録作成時 | 管理サービスへ送る保守モード開始要求を一意に識別する値。 |
| 送信時刻 | 要求送信直前 | 管理サービスへの送信を開始する時刻。 |
| 管理サービス応答結果 | 応答受信時 | 管理サービスから受けた応答の結果。開始済みを示すかどうかを判定できる形で保存する。 |

要求IDには一意性制約を設ける。管理サービス応答結果は応答受信前には未設定とし、応答受信後に同じ保守モード開始監査記録へ反映する。記録作成または送信時刻の保存に失敗した場合は要求を送らない。送信後に管理サービス応答結果の保存に失敗した場合は運用上の異常として通知するが、同じ要求の自動再送は行わない。

## 7. 障害時の扱いと設計上の限界

- 要求送信前にプロセスが停止した場合でも、すでに保守モード開始監査記録が作成されていれば、同じ要求は自動再送しない。
- 要求送信後に応答を保存する前にプロセスが停止した場合、開始済み応答待ち状態を維持し、同じ要求は自動再送しない。
- ローカルの永続化と外部の管理サービスへの送信は一つの原子的な処理にはできない。このため、「実際には送信されなかったが記録だけが残る」可能性を完全には排除できない。本設計では、元要求の再送禁止を優先し、自動再送は行わない。
- タイムアウト後の復旧方法、開始済みを示さない応答を受けた後の運用、要求IDの採番元と同一要求の判定範囲は、元要求では未定義である。実装前に別途決定が必要である。

## 8. 要求との対応

| 元の要求 | 設計箇所 |
|---|---|
| 変更承認記録が承認済み | 3節の変更承認済み条件 |
| アクティブな利用者セッションが0件 | 3節の利用者セッション不在条件 |
| 予定開始時刻に到達 | 3節の予定開始時刻到達条件 |
| 三条件をすべて満たした場合だけ送信 | 3節の論理積、4節の手順1〜5 |
| 開始済み応答までは同じ要求を再送しない | 4節の手順3〜8、5節、7節 |
| 要求ID、送信時刻、応答結果を監査用に保存 | 6節 |
