# 保守モード開始機能 参照名称対応表

この表は、元要求、既存草稿の表現、設計で使用する正式名称の対応を固定する。設計文書は「正式名称」列を基準とし、未定義の総称を追加しない。

| 参照ID | 元要求・草稿の表現 | 正式名称 | 種別 | 指示対象・定義 |
|---|---|---|---|---|
| REF-01 | 変更承認記録が承認済み | 変更承認済み条件 | 前提条件 | 対象変更の承認状態が `APPROVED` |
| REF-02 | アクティブな利用者セッションが0件 | セッション不在条件 | 前提条件 | 判定時のアクティブ利用者セッション数が `0` |
| REF-03 | 予定開始時刻に達している | 予定開始時刻到達条件 | 前提条件 | DB現在時刻が予定開始時刻以上 |
| REF-04 | 三つの条件をすべて満たす／保守移行点を満たす | 保守モード開始可能条件 | 複合条件 | REF-01、REF-02、REF-03の論理積（AND） |
| REF-05 | 開始処理 | 保守モード開始要求送信 | 外部操作 | 管理サービスの開始APIを呼び出す操作 |
| REF-06 | 同じ要求 | 同一の保守モード開始要求IDを持つ要求 | 同一性 | UUIDで識別される一回の開始要求 |
| REF-07 | 保守移行点の間 | 開始要求ID設定後から開始済み確定まで | 状態・期間 | `request_id IS NOT NULL AND state != STARTED`。`AWAITING_START_RESPONSE` と `REVIEW_REQUIRED` を含む |
| REF-08 | 要求ID | 保守モード開始要求ID | 監査項目 | 一回の要求に割り当て、変更しないUUID |
| REF-09 | 送信時刻 | 保守モード開始要求送信時刻 | 監査項目 | 外部送信呼び出し直前にDBから取得して保存する時刻 |
| REF-10 | 結果／管理サービスの応答結果 | 管理サービス開始応答結果 | 監査項目 | `PENDING`、`STARTED`、`NOT_STARTED`、`DELIVERY_UNKNOWN` のいずれか |
| REF-11 | 開始済みの応答 | 管理サービス開始済み応答 | 外部応答 | 管理サービスが保守モード開始済みを確定した応答 |
| REF-12 | 結果を記録する | 開始要求監査記録を保存する | 永続化操作 | REF-08、REF-09、REF-10と判定根拠を対応付けて永続化 |

## 使用禁止または単独使用禁止の表現

| 表現 | 扱い |
|---|---|
| 保守移行点 | 定義が複合条件か状態か判別できないため使用しない |
| 開始処理 | 外部要求送信を指す場合は「保守モード開始要求送信」に置換する |
| 同じ要求 | 単独では使わず「同一の保守モード開始要求IDを持つ要求」とする |
| 結果 | 単独では使わず「管理サービス開始応答結果」とする |

## 対応完全性

- 元要求の三前提条件：REF-01〜REF-03
- 三条件のAND：REF-04
- 外部送信：REF-05
- 非再送の対象と期間：REF-06〜REF-07
- 必須監査項目：REF-08〜REF-10
- 応答終点：REF-11
- 保存操作：REF-12
