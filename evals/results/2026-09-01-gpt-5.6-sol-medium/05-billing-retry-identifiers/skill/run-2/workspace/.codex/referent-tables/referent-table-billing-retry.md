| ID | 出典 | 目的 | 具体対象 | 役割 | 前後関係 |
|---|---|---|---|---|---|
| R1 | ユーザー入力「請求APIが429を返した場合」 | 後続の読み取りと保存を開始する契機を限定する | 請求APIからHTTPステータスコード429の応答を受け取ったこと | 開始条件 | 最初に成立し、その後にレスポンス本文の時刻を読む |
| R2 | ユーザー入力「レスポンス本文の再試行可能時刻」 | 再試行を登録できる時刻を判断し、応答履歴へ残す | 429応答の本文が示す、再び請求APIへ要求を送ってよい時刻 | 値 | 429応答を受けた後に読み取り、履歴保存と現在時刻との比較に使う |
| R3 | ユーザー入力「ステータスコード」 | 応答結果を履歴から確認できるようにする | 請求APIから受け取ったHTTPステータスコード | 値 | 応答を受けた後、R2およびR4とともに履歴へ保存する |
| R4 | ユーザー入力「リクエストID」 | 個々の要求と応答履歴を対応づけられるようにする | 請求APIへの要求を識別するために応答から得た文字列 | 値 | 応答を受けた後、R2およびR3とともに履歴へ保存する |
| R5 | ユーザー入力「ステータスコード、再試行可能時刻、リクエストIDは応答履歴へ保存」 | 一回の応答に関する3つの値を履歴の一単位として保持する | 一回の請求API応答について、HTTPステータスコード、再び要求を送ってよい時刻、要求を識別する文字列をまとめた履歴の一項目 | 記録 | R2、R3、R4を得た後に保存する |
| R6 | ユーザー入力「再試行可能時刻が現在より後」 | 過去または現在の時刻を指定した登録を除外する | 429応答の本文から読んだ時刻が、条件を評価する時点の現在時刻より後であること | 開始条件 | R2を読んだ後、スケジューラへ登録する前に評価する |
| R7 | ユーザー入力「同じ請求の再試行がまだキューにない」 | 同じ請求に対する再試行の重複登録を防ぐ | 同じ請求に対して後で請求APIへ要求を送る予定が、評価時点でキューに一件も存在しないこと | 開始条件 | スケジューラへ登録する前に評価する |
| R8 | ユーザー入力「再試行可能時刻が現在より後で、同じ請求の再試行がまだキューにない場合だけ」 | スケジューラへ登録してよい場合を一つの真偽値で表す | 429応答の本文から読んだ時刻が評価時点の現在時刻より後であり、かつ同じ請求に対して後で請求APIへ要求を送る予定がキューに一件も存在しないこと | 開始条件 | 二つの条件を評価した後、両方が成立した場合だけ登録する |
| R9 | ユーザー入力「スケジューラへ再試行を登録」 | 指定された時刻以後に同じ請求を再び要求できるようにする | 同じ請求を再び請求APIへ送る予定を、429応答の本文から読んだ時刻を指定してスケジューラへ登録する操作 | 手段 | R8が成立した場合に実行し、その完了後にR10となる |
| R10 | ユーザー入力「登録後はスケジューラが実行を開始するまで待機中」 | 登録済みだがまだ実行されていない期間を区別する | スケジューラへの登録が完了しており、同じ請求を再び請求APIへ送る実行はまだ始まっていない状態 | 状態 | R9の完了後に入り、スケジューラが実行を開始した時点で終わる |

| ID | 候補語 | 種別 | 初出定義 |
|---|---|---|---|
| R1 | 命名なし | 命名なし | HTTPステータスコード429との比較を具体的に記述する。 |
| R2 | `retryAt` | 確立語 | `retryAt`とは、429応答の本文が示す、再び請求APIへ要求を送ってよい時刻を指す値。 |
| R3 | `status` | 確立語 | `status`とは、請求APIから受け取ったHTTPステータスコードを指す値。 |
| R4 | `requestId` | 確立語 | `requestId`とは、請求APIへの要求を識別するために応答から得た文字列を指す値。 |
| R5 | `RetryLog` | 新規語 | `RetryLog`とは、一回の請求API応答について`status`、`retryAt`、`requestId`をまとめて応答履歴へ保存する一項目を指す記録。 |
| R6 | 命名なし | 命名なし | `retryAt > now`として比較を具体的に記述する。 |
| R7 | 命名なし | 命名なし | 同じ請求の再試行がキューに存在しないかを具体的に照会する。 |
| R8 | `canScheduleRetry` | 新規語 | `canScheduleRetry`とは、`retryAt`が評価時点の現在時刻より後であり、かつ同じ請求の再試行がキューに一件も存在しないことを指す開始条件。 |
| R9 | `scheduleRetry` | 新規語 | `scheduleRetry`とは、同じ請求を再び請求APIへ送る予定を、`retryAt`を指定してスケジューラへ登録する操作を指す手段。 |
| R10 | `scheduled` | 新規語 | `scheduled`とは、スケジューラへの登録が完了しており、同じ請求を再び請求APIへ送る実行はまだ始まっていない状態を指す。 |
