| ID | 出典 | 目的 | 具体対象 | 役割 | 前後関係 |
|---|---|---|---|---|---|
| R1 | ユーザー入力「ステータスコード、再試行可能時刻、リクエストIDは応答履歴へ保存」 | 請求APIへの一回の要求に対する応答を後から追跡できるようにする | 請求APIへの一回の要求で得たステータスコード、レスポンス本文から読んだ再試行可能時刻、リクエストIDをひとまとまりにした応答履歴の一項目 | 記録 | 請求APIから429を受け、レスポンス本文を読んだ後に保存する |
| R2 | ユーザー入力「再試行可能時刻が現在より後で、同じ請求の再試行がまだキューにない場合だけ」 | スケジューラへの重複登録と、過去の時刻を使った登録を防ぐ | レスポンス本文から読んだ再試行可能時刻が判定時点の現在より後であり、かつ同じ請求の再試行がキューに存在しない、という二条件がともに成立したかを表す真偽値 | 値 | 429応答の内容を応答履歴へ保存した後、スケジューラへ登録する前に求める |
| R3 | ユーザー入力「スケジューラへ再試行を登録」 | 指定された時刻以後に同じ請求を再び要求できるようにする | 同じ請求の再試行を、レスポンス本文から読んだ再試行可能時刻とともにスケジューラへ登録する操作 | 手段 | R2の二条件がともに成立した場合だけ行う |
| R4 | ユーザー入力「登録後はスケジューラが実行を開始するまで待機中」 | 登録済みだが実行が始まっていない期間を他の期間と区別する | 同じ請求の再試行がスケジューラへ登録された後から、そのスケジューラが再試行の実行を開始する直前までの状態 | 状態 | R3の登録完了で始まり、スケジューラによる実行開始で終わる |
| R5 | ユーザー入力「ステータスコード」 | 応答履歴の一項目にHTTPの結果を残す | 請求APIが返したHTTPステータスコードの値 | 値 | 429応答を受けた後にR1へ保存する |
| R6 | ユーザー入力「レスポンス本文の再試行可能時刻」 | 再試行を登録できるかの判定と登録時刻の指定に使う | 請求APIの429レスポンス本文から読み取った、再試行が可能になる時刻の値 | 値 | 429応答を受けた後に読み取り、R1へ保存してからR2の判定とR3の登録に使う |
| R7 | ユーザー入力「リクエストID」 | 応答履歴から個々の要求を追跡できるようにする | 請求APIへの一回の要求を識別するために応答から得た値 | 値 | 429応答を受けた後にR1へ保存する |

| ID | 候補語 | 種別 | 初出定義 |
|---|---|---|---|
| R1 | `BillingAttempt` | 新規語 | `BillingAttempt`とは、請求APIへの一回の要求で得たステータスコード、429レスポンス本文から読んだ再試行可能時刻、リクエストIDを保持する応答履歴の一項目を指す記録型である。 |
| R2 | `canScheduleRetry` | 新規語 | `canScheduleRetry`とは、429レスポンス本文から読んだ再試行可能時刻が判定時点の現在より後であり、かつ同じ請求の再試行がキューに存在しない、という二条件がともに成立したかを指す真偽値である。 |
| R3 | `scheduleRetry` | 新規語 | `scheduleRetry`とは、同じ請求の再試行を、429レスポンス本文から読んだ再試行可能時刻とともにスケジューラへ登録する操作を指すメソッド名である。 |
| R4 | `retryQueued` | 新規語 | `retryQueued`とは、同じ請求の再試行がスケジューラへ登録された後から、そのスケジューラが再試行の実行を開始する直前までを指す状態名である。 |
| R5 | `status` | 確立語 | `status`とは、請求APIが返したHTTPステータスコードを保持するプロパティ名である。 |
| R6 | `retryAt` | 新規語 | `retryAt`とは、請求APIの429レスポンス本文から読み取った、再試行が可能になる時刻を保持するプロパティ名である。 |
| R7 | `requestId` | 確立語 | `requestId`とは、請求APIへの一回の要求を識別するために応答から得た値を保持するプロパティ名である。 |
