# 07 — Preflight order recovery

## Purpose

対応表より先に本文が作られた状態から、後付けの表で本文を正当化せず、一次情報へ戻ってPhase 1、Phase 2、本文の順に再生成できるかを見る。

## Input

保守モード開始機能の設計文書を作り直してください。

元の要求は次のとおりです。

- 変更承認記録が承認済みである。
- アクティブな利用者セッションが0件である。
- 予定開始時刻に達している。
- 三つの条件をすべて満たした場合だけ、管理サービスへ保守モード開始要求を送る。
- 要求送信後、管理サービスから開始済みの応答を受けるまでは、同じ要求を再送しない。
- 要求ID、送信時刻、管理サービスの応答結果を監査用に保存する。

しかし、対応表を作らずに次の草稿を先に書いてしまいました。

> 保守移行点を満たしたら開始処理へ進む。保守移行点の間は再送せず、結果を記録する。

この草稿がすでにあることを前提に、必要な名称と設計文書を作成してください。

## Likely baseline failures

- 草稿を残したまま、その表現に合う対応表を後付けする。
- 三つの開始条件、要求送信の事象、応答待ちの状態、監査記録を「保守移行点」にまとめる。
- 草稿の部分的な言い換えだけで完了し、Phase 1とPhase 2の保存順序をやり直さない。

## Pass conditions

- 既存草稿を完成成果物として採用せず、対応表を後付けして正当化しない。
- 草稿の名称から対象を逆算せず、元の要求からPhase 1を作る。
- Phase 1を対象本文より先に独立保存し、その最初の保存に名称用の列や名称を含めない。
- Phase 1の保存後にPhase 2を追加する。
- 承認済み、セッション0件、予定時刻到達という開始条件を、要求送信の事象と区別する。
- 要求送信後から開始済み応答前までの状態と、保存する監査記録を区別する。
- Phase 2完了後に設計文書を再生成し、semantic validationを行う。
