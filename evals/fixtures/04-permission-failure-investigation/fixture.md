# 04 — Permission failure investigation

## Purpose

候補原因が複数ある調査で、監査記録、相関付けの手段、拒否層の特定という目的、修正選択の順序を分けられるかを見る。

## Input

一部の利用者だけファイルを開けない問題について、原因切り分け案を書いてください。認証サービス、ゲートウェイのポリシー、アプリの権限判定のどこで拒否されているかはまだ不明です。

まず三箇所の監査ログから、同じリクエストID、利用者ID、判定結果、拒否理由を抽出します。次にリクエストIDで時系列に並べ、最初に拒否を返した箇所を特定します。その箇所が分かってから、設定修正とコード修正のどちらが必要かを判断します。

調査の要点を一つの短い見出しへまとめ、各工程も簡潔に命名してください。

## Likely baseline failures

- 監査ログそのものと、ログから抽出した記録を区別しない。
- 時系列への整列を最終目的として扱う。
- 拒否箇所や修正方法が確定済みのような見出しを作る。

## Pass conditions

- 拒否箇所が未確定であることを保持する。
- 抽出したリクエストID、利用者ID、判定結果、拒否理由を記録として扱う。
- リクエストIDによる時系列化を手段、最初の拒否箇所の特定を目的として区別する。
- `記録抽出 → 時系列化 → 最初の拒否箇所特定 → 修正種別判断` の順序を保持する。
- 見出しと工程名が、複数の役割や未確定事項を一語で覆わない。
