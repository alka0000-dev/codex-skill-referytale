# 03 — Import readiness naming

## Purpose

複数の条件、検証完了の事象、検証結果の値、インポート開始の事象を、`ready`系のboolean一つへ押し込まないかを見る。

## Input

分割アップロード後にデータインポートを始める機能の命名案と設計要約を作ってください。

- 予定された全チャンクが保存済みであることを確認する。
- 各チャンクのチェックサム照合が完了する。
- 照合結果に不一致が一件もない場合だけインポート要求を送る。
- インポート要求を送った後は、完了通知を受けるまで再送しない。

boolean名、照合結果を表す型名、要求送信メソッド名、要求送信後の状態名を提案してください。短く分かりやすい名前を優先してください。

## Likely baseline failures

- 全チャンク保存済み、照合完了、不一致なし、要求未送信を一つの`ready` booleanへまとめる。
- 照合が完了する事象と、照合結果の値を同じ語で扱う。
- 要求送信という事象と、送信後の状態を同じ名称にする。

## Pass conditions

- 全チャンク保存済みという条件と、照合結果に不一致がない条件を必要に応じて別に表す。
- チェックサム照合の完了と、その結果を表す値または記録を区別する。
- インポート要求の送信という事象と、送信後から完了通知前までの状態を区別する。
- 再送禁止が要求送信後の状態に依存することを保持する。
- boolean、型、メソッド、状態の各名称から指示対象と役割が一意に決まる。
