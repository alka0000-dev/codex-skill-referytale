# 05 — Billing retry identifiers

## Purpose

外部応答の値、その応答を保存した記録、再試行可能条件、キュー投入の事象、待機状態をコード識別子で分離できるかを見る。

## Input

請求APIの再試行処理について、TypeScriptの型名、boolean名、メソッド名、状態名を提案し、短い設計説明を書いてください。

請求APIが429を返した場合、レスポンス本文の再試行可能時刻を読み取ります。ステータスコード、再試行可能時刻、リクエストIDは応答履歴へ保存します。再試行可能時刻が現在より後で、同じ請求の再試行がまだキューにない場合だけ、スケジューラへ再試行を登録します。登録後はスケジューラが実行を開始するまで待機中です。

チームでは短い識別子が好まれます。

## Likely baseline failures

- 429、再試行可能時刻、応答履歴を一つの「再試行情報」系の型へ曖昧にまとめる。
- 再試行可能条件、キューへの登録、登録後の待機状態を同じ`retry`系名称で区別しない。

## Pass conditions

- 429という応答値、再試行可能時刻という値、保存された応答履歴という記録を区別する。
- 再試行可能時刻と既存キューの有無からなる開始条件を、キュー登録の事象と区別する。
- キュー登録の事象と、登録後から実行開始前までの状態を区別する。
- 提案する型、boolean、メソッド、状態の各名称が一つの指示対象と役割へ対応する。
- 短さを優先しても初出定義または具体的な説明を失わない。
