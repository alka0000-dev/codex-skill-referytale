# Referent before label

<!-- codex-runtime-summary -->
- IMPORTANT: 設計、調査報告、原因切り分け、対策案、命名、推論順序の要約で新しい名称・抽象語を導入する可能性がある場合、または適用要否を判断できない場合は `referytale` skill を使用する。
- IMPORTANT: 指示対象を確定する前に名称を作らない。対象・役割・前後関係が確定していない内容を作業ラベルで覆わない。
- IMPORTANT: 対応表に存在しない新規語を対象本文へ直接導入しない。新しい語が必要になった場合はPhase 1へ戻る。
- IMPORTANT: Phase 1より先にCodexが対象本文を生成した場合、後付けの対応表で正当化しない。その本文を完成成果物として採用せず、`referytale` skillの復旧手順で再生成する。
- IMPORTANT: 対象作業で `referytale` skillを読み込めない場合は対象本文を生成しない。利用不能をユーザーへ報告する。
<!-- /codex-runtime-summary -->

設計・調査・命名では、「語を先に作り、その語に対象を合わせる」生成順序を禁止する。

新しい名称や抽象語を導入する可能性がある作業、または適用要否を判断できない作業では `referytale` skill を使用する。

Phase 1より先に同じ実行内で生成した対象本文は、後付けの対応表で継続せず、`referytale` skillに従って再生成する。ユーザーが作業開始前から持っていた文書や入力資料は破棄しない。

`referytale` skillを読み込めない場合は、詳細手順を推測して代替せず、対象本文の生成を止めて利用不能を報告する。

詳細な手順、対応表の形式、検証方法、問題発生時の戻り方は `referytale` skill を正本とする。このRuleでは個別の誤用語を管理しない。
